## 2026-07-31 — Phase 2: crash risk model

- **Environment fixes:** LightGBM couldn't import (`libomp.dylib` not loaded) — installed via `brew install libomp` (one-time, system-level, outside `.venv`). Also installed `shap` and `pyarrow` (needed for `outputs/risk_scores.parquet`).
- **Step 0 (recover lost features):** tested `ox.features_from_place` for footways/street lamps — came back in real volume (70,719 footways, 6,860 lamps), so added them to `build_features.py`. `sidewalk_len_100m` (summed footway length within 100m, using full-segment length rather than exact circle-clipping — a documented approximation, cheap and reasonable since OSM footway segments are short) has 50.7% coverage and was kept. `n_street_lamps_100m` had only 4.5% coverage — below the spec's ~20% threshold — so it was **dropped** (computed but excluded from the written schema) as noise, per spec. Re-ran `fetch_osm.py`/`build_features.py --force`/`validate_phase1.py` — all checks still pass.
- Wrote `spatial_kfold(gdf, n_splits, cell_size_m)` in `src/utils/geo.py`: buckets intersections into whole 2km grid cells, then greedily bin-packs cells into folds (biggest cells first, always to the currently-smallest fold) for balanced fold sizes despite uneven intersection density. Kept label-agnostic (no crash-count awareness) so Phase 6 can reuse it.
- Wrote `src/models/risk_model.py`: 10 features after dropping `int_id`/`osmid`/`geometry`/the target/the leakage column, **and** `has_lighting_tag`/`has_sidewalk` (both always `False` — zero information, flagged back in Phase 1). `highway_class_max` handled as a native LightGBM category, no one-hot encoding. Used `LGBMRegressor` (sklearn wrapper) over the raw `Booster` API specifically so `sklearn.inspection.PartialDependenceDisplay` would work directly.
- 5 spatial folds all had >=30 positives (38-81 each), so no fallback to 3 folds was needed. Poisson objective trained cleanly on every fold (no misbehavior triggers fired), so no fallback to a binarized target was needed either.
- **Results (spatially-blocked CV, mean of 5 folds):** ROC-AUC 0.919, PR-AUC 0.080 (base rate 0.0075 — **~10.6x base rate**), Poisson deviance 0.056, **recall@top-5% = 51%** (investigating the top ~1,959 intersections would catch about half of all pedestrian crashes). The random-split baseline scored almost identically (ROC-AUC 0.919, PR-AUC 0.087) — a genuinely small spatial-vs-random gap, worth noting since it suggests the signal here isn't just spatial autocorrelation leaking across folds.
- **Exit gate met on both counts:** ROC-AUC 0.919 >= 0.70, PR-AUC 0.080 >= 0.023 (3x base rate). No fallback to the midblock-band target was needed.
- **What the model learned:** `highway_class_max` and `dist_to_transit_m` dominate feature importance, followed by `mean_lanes` and `sidewalk_len_100m` — busier, higher-class roads closer to transit carry more predicted risk, which matches how pedestrian exposure concentrates in a car-oriented Sun Belt metro. `max_speed_mph` shows a clear positive SHAP relationship (sanity-check correlation +0.866, so the required "higher speed = higher risk" check passes) with one sensible wrinkle: partial dependence dips slightly at the highest speeds (60-75 mph), which is almost certainly motorway junctions where pedestrians are rarely present at all, not the model contradicting itself. `has_marked_crossing` and `is_signalized` both push risk *up* rather than down in the SHAP plot — a real and expected artifact of observational data, since crossings/signals tend to get installed where pedestrian activity (and therefore risk) is already high, not randomly.
- Wrote `outputs/figures/{feature_importance_gain,shap_summary,pdp_speed_lanes}.png`, `outputs/risk_scores.parquet` (39,183 rows: `int_id`, `risk_score`, `risk_percentile`), `models/risk_lgbm.txt`, `outputs/phase3_candidates.csv` (top 2,000 `int_id`s by risk score).

**Phase 2 exit gate met.** No known-risk fallback needed — 459 crashes over the expanded study area turned out to be enough signal.
